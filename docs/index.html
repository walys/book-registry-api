Book Registry API

A RESTful API built with Laravel for managing books, featuring token-based authentication, CRUD operations, input validation, and user-specific data access.

Laravel PHP 8.3 REST API Sanctum

Features

Token Authentication

Secure login and logout using Laravel Sanctum.

Book Management

Create, list, view, update, and delete books.

Input Validation

Dedicated Form Requests validate incoming data.

Data Ownership

Users can access and manage only their own books.

JSON Responses

API responses use JSON, including validation errors.

Automated Tests

Feature tests cover authentication, CRUD, and validation.

Installation

1. Clone the repository

git clone YOUR_REPOSITORY_URL
cd book-registry-api
Replace YOUR_REPOSITORY_URL with the actual URL of your Git repository.

2. Install dependencies

composer install

3. Configure the environment

cp .env.example .env
php artisan key:generate

On Windows, you can also copy .env.example manually and rename the copy to .env.

4. Configure the database

Update the database settings in your .env file. For example: 

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=book_registry_api
DB_USERNAME=root
DB_PASSWORD=

Create the database before running the migrations.

5. Run migrations and seeders

php artisan migrate
php artisan db:seed

The seeder creates the development user configured by the project. Check the seeder source for the credentials used.

6. Start the development server

php artisan serve

Base URL: http://127.0.0.1:8000

Never commit your .env file, passwords, or access tokens to version control.

Authentication

Protected endpoints require a valid Sanctum access token in the HTTP Authorization header. 

Authorization: Bearer YOUR_ACCESS_TOKEN
Accept: application/json

Login

POST /api/login

{
    "email": "your-email@example.com",
    "password": "your-password"
}

The response includes an access token to use in authenticated requests.

Get authenticated user

GET /api/user

Logout

POST /api/logout

Logout revokes the current access token. Subsequent requests using that token should return 401 Unauthorized.

Book Endpoints

All book endpoints require authentication.

Method Endpoint Description
GET /api/books List the authenticated user's books
POST /api/books Create a book
GET /api/books/{id} Retrieve a specific book
PUT /api/books/{id} Update a book
PATCH /api/books/{id} Partially update a book
DELETE /api/books/{id} Delete a book

Create a book

POST /api/books

{
    "name": "Clean Code",
    "isbn": "9780132350884",
    "value": 99.90
}

Example response

{
    "id": 1,
    "user_id": 1,
    "name": "Clean Code",
    "isbn": "9780132350884",
    "value": "99.90",
    "created_at": "2026-01-01T12:00:00.000000Z",
    "updated_at": "2026-01-01T12:00:00.000000Z"
}
This is an illustrative response. IDs and timestamps are generated by the application, and the returned values depend on the request. The decimal value is serialized as a string by the model's decimal:2 cast.

Validation Rules

Field Create Update Rules
name Required Optional; required when provided String, maximum 255 characters
isbn Optional Optional String containing digits only, or null
value Optional Optional Numeric, minimum 0, or null
  • On update, omitted fields remain unchanged.
  • An empty name is not accepted when the field is provided.
  • ISBN is stored as a string to preserve leading zeros.
  • Invalid input returns 422 Unprocessable Entity in JSON format.

Data Ownership & Security

  • Book records are scoped to the authenticated user.
  • Users cannot retrieve, update, or delete another user's books.
  • Requests for books outside the user's scope return 404 Not Found.
  • Requests to protected endpoints without valid authentication return 401 Unauthorized.
  • Credentials and access tokens should never be committed to the repository.

HTTP Status Codes

Automated Tests

Run the test suite with:

php artisan test

The feature tests cover:

  • Authentication and logout.
  • Book creation, listing, retrieval, updating, and deletion.
  • Validation errors and partial updates.
  • User ownership and access restrictions.
  • JSON responses and unauthorized requests.
The automated test suite uses an in-memory SQLite database, keeping tests isolated from the development database.

Project Architecture

  • Controllers: Handle HTTP requests and responses.
  • Form Requests: Centralize request validation.
  • Services: Encapsulate book management operations.
  • Models: Represent users and books and their relationships.
  • Feature Tests: Verify API behavior and access rules.
